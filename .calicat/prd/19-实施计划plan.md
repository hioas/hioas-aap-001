# 实施计划（plan）

> 配套 spec.md。里程碑 M0–M3 逐阶段可交付可验收。人日均为估算非承诺。

## 全局前提

技术栈 Java 25 + Spring Boot（BOM 管理 4.1.1）+ Maven + PostgreSQL；聚合 POM import BOM 第三方不写版本；集成红线 new-api 零源码改动；编译红线未过模拟验证禁止写生产；3 人并行（后端主线+检测/编译器+前端）；dev/staging/prod 三套，new-api 专用最小权限账号+独立只读 DB 账号。

## M0 — 打通"凭证 → 检测 → 报告"闭环（2 周，不含指纹）

交付物 M0-D1~~D9：工程脚手架（import BOM+lombok/log4j2+health）、账号认证（短信验证码+JWT+4 角色）、供应商档案、凭证管理（AES-256-GCM 加密+脱敏+预检）、SSRF 出站防护、检测引擎 4 项（D1 TTFT/D3 一致性/D4 RPM/D6 缓存命中）、检测报告（四段解释+模板+PDF）、短信通知（hioas-sms）、供应商端前端（注册/登录/凭证/进度/报告）。
验收：AC-01~~AC-18 主链路 + AC-29 SSRF + AC-30 脱敏。小计 25–40 人日。

## M1 — 报价 → 编译 → 同步 new-api（3 周，生成待确认模式）

交付物 M1-D1~~D10：报价单数据模型与编辑、报价校验、计费表达式编译器（C1–C10 全覆盖）、模拟校验器（V1–V6）、人工确认页（三栏对照）、new-api 集成适配器、价格写入适配器（BillingOptionWriter 默认 DB 策略）、幂等与回读、审核流、管理端前端。
关键前置实测（M1 首日）：① billingexpr 是否支持变量绑定；② new-api option 写入 HTTP 端点是否存在（否则 DB 策略）。
验收：AC-19~~AC-27 + AC-31 编译失败定位 + AC-33 同步失败重试 + AC-32 红线。小计 20–31 人日。

## M2 — 合同（线下）+ 打款状态 + 小时用量统计（3 周）

交付物 M2-D1~~D8：合同模块（模板生成+盖章件上传+状态机）、打款记录（仅记录不流转）、上架启用（PAID+SYNCED→PUBLISHED+tag 启停）、自建小时用量表（T+5min 聚合）、缓存字段解析、对账视图、供应商端用量视图、审计日志。
验收：AC-28、AC-34~~AC-40。小计 18–28 人日。

## M3 — 指纹与真实源进阶探测（持续，首版 2 周）

交付物 M3-D1\~D6：基线库（官方源采集）、D7 五子项（自我认知/Tokenizer/行为题库 40 题/概率/上下文边界）、D7 合成与否决、D8 证据线、定期复测（recheck\_interval\_days 30 天）、报告风险提示。
验收：AC-35 D7 一票否决 + AC-34 不可测权重重分配。小计 21–34 人日。

## 总估算与风险管理

合计 84–133 人日。风险：SSRF 高（M0-D5 强制代理+黑名单）；Key 泄露高（M0-D4 加密+脱敏）；编译错误高（M1-D4 模拟校验闸门+红线）；指纹概率高（M3 多子项交叉+置信度+一票否决）；RPM 压测打爆中；new-api 升级中；缓存缺口中（M2 自建表）。
