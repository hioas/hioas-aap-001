# 业务架构与领域模型

## 1. 战略设计：领域划分

| 层次             | 定义       | 本平台能力                                         | 投入   |
| -------------- | -------- | --------------------------------------------- | ---- |
| 核心域 Core       | 差异化壁垒自研  | ① 检测验证（多维指纹+可解释报告）② 计费编译（报价→billingexpr+模拟求值） | 最高投入 |
| 支撑域 Supporting | 业务必需非差异化 | 供应商档案、凭证管理、报价编辑、审核流转、合同打款留痕、用量聚合、通知           | 自建从简 |
| 通用域 Generic    | 成熟可复用    | 账号认证（AuthSphere）、短信（hioas-sms）、对象存储、审计框架      | 优先复用 |

**边界结论**：new-api 是外部系统，AAP 通过其管理 API 读写（零源码改动）。

## 3. 上下文映射

iam →(OHS/发布语言)→ provider →(Customer/Supplier)→ credential →(事件 CredentialSubmitted)→ detection →(ProbeCompleted/DetectionFinished)→ report →(DetectionPassed/Failed)→ provider 状态机 → quote →(提交报价)→ review →(QuoteApproved)→ contract →(ContractSigned)→ settlement →(PaymentConfirmed)→ sync。quote →(请求编译)→ compilation →(编译产物)→ sync。sync →(ACL 防腐层)→ new-api。sync →(渠道绑定/游标)→ usage →(用量归档)→ settlement。所有上下文 → support（横切）。

防腐层 NewApiAcl 是三处翻译的唯一落点：channelName↔Channel.Name、apiKeyCipher↔Channel.Key（解密后透传不落日志）、modelName 列表↔Channel.Models、shortCode↔Channel.Tag、编译产物↔option billing\_setting.billing\_expr\[model]。

## 4. 领域实体与聚合根

关键聚合根：ProviderAccount（iam）、Provider（provider，含主状态机）、Credential（credential）、DetectionJob（detection，含 configSnapshot 快照）、Report（report）、Quote（quote，最大聚合，含明细行+规则+版本快照）、CompiledExpression（compilation，确认后不可变）、ChannelBinding + SyncTask（sync）、UsageHourly（usage）、AuditLog（support，append-only）。

聚合规则：跨聚合只用 ID 引用；Quote 是唯一可变大聚合（单次编辑原子提交）；Report 与 DetectionJob 一对一但独立成聚合；CompiledExpression 确认后不可变；AuditLog 严格 append-only。

核心实体不变式：

* Provider：status=QUOTE\_SUBMITTED 不得改凭证；PUBLISHED/SUSPENDED 不得删资质。
* Credential：同供应商至多 1 条主凭证；baseUrl 须合法 http(s) 且过 SSRF 预校验。
* DetectionJob：同 credentialId 同时至多 1 个 QUEUED/RUNNING 任务。
* Quote：peakRanges 不重叠、tiers 覆盖 \[0,+∞) 无空洞、单价≥0、倍率>0 有限、modelName 不重复。
* CompiledExpression：VERIFIED/CONFIRMED/PUBLISHED 必须 verifyRun.passed=true；CONFIRMED 后表达式不可变。

## 5. 领域服务（无状态业务规则）

ScoreAggregator（8 项加权+权重重分配+一票否决）、ConfidenceEvaluator、ProbeCostEstimator、FingerprintMatcher、TimeRuleCompiler（hour/weekday）、TierRuleCompiler（len 分档禁 p）、BasePriceCompiler、RequestRuleCompiler（|||）、ExpressionComposer（外层档×内层时段）、QuoteConflictValidator、ExpressionSimulator（样例向量求值）、ChannelNameGenerator、BillingExprMerger、PricingConverter。

## 6. 领域事件清单（42 个，E01–E42）

关键：ProviderRegistered、CredentialSubmitted、DetectionJobQueued/Started、ProbeCompleted、DetectionFinished、DetectionPassed/Failed、ReportGenerated、ProviderManuallyReleased、QuoteCreated/Submitted/Withdrawn、QuoteRejected/Approved、ContractIssued/Signed、PaymentRecorded/Confirmed、ExpressionCompiled/VerifyFailed/Confirmed、SyncTaskCreated、ChannelBound、PriceWritten、SyncSucceeded/PartiallyFailed/Failed/RolledBack、UsageHourAggregated、ProviderSuspended/Resumed、CredentialRevealed、DegradationAlertRaised。

投递语义：至少一次，消费方按 eventId 去重；同 aggregateId 按 version 单调递增；事务性发件箱（Outbox）。

## 7. 状态机汇总（权威定义）

供应商主状态 ProviderStatus：PENDING\_CREDENTIAL→DETECTING→(DETECT\_PASSED|DETECT\_FAILED)；DETECT\_FAILED→DETECTING；DETECT\_PASSED→QUOTING→QUOTE\_SUBMITTED→(QUOTING|CONTRACT\_PENDING)→SIGNED→PAID→PUBLISHED⇄SUSPENDED。DETECT\_FAILED→QUOTING 仅经 ProviderManuallyReleased（带操作人备注）。

检测任务 DetectionJob.status：QUEUED→RUNNING→(PARTIAL→)FINISHED；RUNNING→FAILED（401/403 不重试）；网络失败重试≤2 次。报价单 Quote.status：DRAFT→SUBMITTED→(DRAFT|UNDER\_REVIEW)→(REJECTED→DRAFT|APPROVED→CONVERTED)。编译 CompiledExpression.status：DRAFT→(VERIFIED→CONFIRMED→PUBLISHED)|VERIFY\_FAILED→DRAFT。同步 SyncTask.status：PENDING→RUNNING→(SUCCESS|PARTIAL\_FAILED→RUNNING|FAILED)→(ROLLED\_BACK)。渠道 ChannelBinding.status：NOT\_SYNCED→SYNCED→ENABLED⇄DISABLED。

## 8. 与 new-api 的边界（防腐层职责）

唯一出口：全平台只有 sync 的 ACL 允许调 new-api；协议隔离（new-api 字段名只在 ACL 内）；鉴权隔离（专用最小权限 Token）；幂等（idempotencyKey+写前对比+写后回读）；降级（new-api 不可用进重试队列不阻塞，可降级人工操作）；版本风险（登记版本指纹+契约测试）。

## 9. 架构约束清单（供开发执行）

* 核心域禁止直接依赖 new-api 客户端，须经端口接口注入。2. 所有外部 HTTP 出站经统一出站网关（SSRF+超时+重试+脱敏）。3. 凭证明文读写只在 credential 上下文与 detection 内存探测路径，任何日志/异常栈/指标不得含明文。4. 状态流转必须经领域方法。5. 报告文案禁用词校验渲染前拦截。6. 配置/模板变更版本化+快照冻结。7. 跨上下文查询走只读视图，禁止跨上下文联表写。
