# PRD — 检测验证引擎

> 对应模块 M4（检测引擎）与 M5（检测报告）。本模块是本产品的差异化核心。

## 1. 目标与定位

在供应商模型上架前，用多维度自动探测回答三个问题：

* 端点能用、够快、够稳吗？（性能）
* 行为与宣称的模型一致吗？（真实性）
* 计费特性（缓存、限速）与买到的相符吗？（商业）

**定位声明（重要）**：本引擎输出的是证据与置信度，不是"真/假"判决。系统不得在任何界面表述"已验证该模型为正品"。标准措辞：**"未发现与宣称模型不一致的迹象（置信度：高/中/低）"**。

## 2. 检测项规格（8 项）

每项含：探测方法 → 原始指标 → 打分 → 证据 → 局限。打分统一 0–100，通过线可配（默认 60）。

### D1. TTFT（首 token 延迟）

* 方法：`stream=true`，测请求发出 → 首个 SSE data chunk 到达毫秒数。默认 10 次，间隔 1s。
* 指标：P50/P90/均值/标准差。
* 打分：`score = clamp(100 * (threshold_p90_ms - p50) / (threshold_p90_ms - threshold_best_ms), 0, 100)`；默认 best=200ms、p90=3000ms（可配）。
* 局限：受网络路径影响，不区分首 token 慢的原因。

### D2. P50 延迟（端到端）

* 方法：固定 prompt（500 token 输入 / 256 输出），记总耗时与输出 TPS。
* 打分：`score = clamp(100 * (tps - tps_min) / (tps_cap - tps_min), 0, 100)`，默认 tps\_min=5、tps\_cap=80。

### D3. 一致性（Determinism）

* 方法：同 prompt，`temperature=0, top_p=1`，并发 N 次（默认 8），比对响应文本。
* 指标：一致性率 = 完全相同条数 / N。一致性率高是"正常"但不是"证明"（上游结果缓存也会全同）。

### D4. RPM（每分钟请求数）

* 方法：阶梯加压，从 5 req/s 起每 5 秒 +5，直到 429 或达上限（默认 60 req/s 硬保护）。用 max\_tokens=1 降成本。
* 打分：对比申报值 `score = clamp(100 * 实测 / 申报, 0, 100)`；未申报只报告不评分。
* 局限：压测产生真实费用，须先估成本设上限，可能触发上游封禁。

### D5. TPM（每分钟 token 数）

* 方法：固定并发最大化 token 消耗，统计 60 秒窗口内成功消耗 total tokens。默认仅测 1 个窗口。

### D6. 缓存命中（Cache）

* 方法：发送足够长 prompt（默认 ≥2000 token）两次，第二次紧接第一次（TTL 内）；读响应用量字段（OpenAI `usage.prompt_tokens_details.cached_tokens`，Claude `cache_read_input_tokens`/`cache_creation_input_tokens`）。
* 打分：命中→100；未命中→0（写"未观测到缓存命中"）；上游不返回字段→"不可测"不计入总分。
* 局限：与 D3 强相关，上游缓存会同时推高 D3。

### D7. 模型指纹（Model Fingerprint）★ 全系统最需克制的一项

5 条子证据线加权合成：

* ① 自我认知（权重 0.15）：问模型身份/训练截止/开发商。
* ② Tokenizer 指纹（权重 0.25）：对固定多语言文本集取 prompt\_tokens，与基线库比对（容差 ±2%）。
* ③ 行为指纹（权重 0.35）：题库回归——N 道难度分层题（默认 40），得分向量与基线对比（余弦相似度/档位比对）。
* ④ 概率指纹（权重 0.15，可选）：logprobs top-5 分布，上游不支持则跳过。
* ⑤ 上下文/能力边界（权重 0.10）：max\_context 二分查找与规格比对。

打分：`score = Σ(wᵢ × sᵢ)`；子项不可测则权重按比例重分配。
置信度：可测子项 ≥4 且一致→高；3 项→中；≤2→低（强制披露）。
**降级判定**：行为指纹相似度 <0.7 告警；tokenizer 偏离 >5% 告警；上下文长度显著小于宣称告警；自我认知冲突记录（低权重）。

### D8. 真实源（Upstream Origin）

探测：① DNS/网络（IP→ASN/归属地）② TLS 证书（Subject/SAN/Issuer）③ 响应头（server/x-request-id/cf-ray/x-amzn-*/anthropic-*）④ 错误格式指纹 ⑤ /v1/models 列表 ⑥ 时间/语言特征。
**建议只输出证据，不纳入总分**（默认权重 0）。

## 3. 总分与通过判定

总分 = Σ(各检测项得分 × 权重)。

| 检测项        | 默认权重 | 计入总分      |
| ---------- | ---- | --------- |
| D1 TTFT    | 0.10 | ✅         |
| D2 P50/TPS | 0.15 | ✅         |
| D3 一致性     | 0.10 | ✅         |
| D4 RPM     | 0.10 | ✅（未申报重分配） |
| D5 TPM     | 0.10 | ✅（未申报重分配） |
| D6 缓存命中    | 0.10 | ⚠️ 可测才计入  |
| D7 模型指纹    | 0.35 | ✅ 核心项     |
| D8 真实源     | 0.00 | ❌ 仅证据     |

通过判定：总分 ≥ pass\_score（默认 70）**且**无"一票否决项"（默认 D7<40 否决）。
结果三态：通过 / 未通过 / 人工复核（总分在 pass\_score±10 区间或存在不可测项）。

## 4. 报告生成（M5）

报告结构：封面（供应商/时间/凭证脱敏/综合评分/结论）→ 结论摘要 → 分项评分总览（雷达图/条形图）→ 逐项详情 → 风险提示 → 附录 → 免责声明。

每项必带四段式解释：这项测什么 / 我们怎么测的 / 结果说明 / 为什么重要与边界。

模板可配：检测项启停、阈值与权重、一票否决规则、报告模板（Logo/标题/章节顺序/原始数据/免责文案）、输出格式（在线/PDF/图片分享）。

## 5. 任务调度与执行

* 异步：提交凭证后创建 DetectionJob 入队；单凭证互斥（同一时刻仅 1 个任务）；分项并行（D4/D5 压测串行）；单项超时（D1–D3/D6–D8 各 3 分钟，D4/D5 各 10 分钟）；网络失败重试 2 次（指数退避），鉴权失败不重试；成本保护。

安全约束：SSRF 防护（专用代理、禁内网/环回/元数据、仅 http(s)、重定向≤3、响应体≤10MB）；凭证 AES-256 加密；压测限流（全局并发上限、每日配额、RPM 硬上限 60）；端点归属（可选 challenge 签名串）。

触发时机：首次（提交凭证后自动）、重测（修改凭证/人工点击）、定期复测（默认 30 天，异常告警）。

## 6. 数据结构（关键字段）

DetectionJob（id/provider\_id/credential\_id/status/trigger\_type/config\_snapshot/total\_score/result/confidence）
DetectionResult（job\_id/probe\_code/status/score/metrics/evidence/explanation/weight\_used）
Report（job\_id/template\_id/template\_snapshot/rendered\_html/pdf\_url）

## 7. 验收标准（本模块）

A1 8 项可独立启停；A2 每项产出原始指标+证据+四段解释；A3 一键否决生效（D7<40 总分再高也不通过）；A4 不支持 logprobs/缓存字段时标记"不可测"且权重正确重分配；A5 SSRF 防护拒绝内网地址；A6 凭证加密存储且接口脱敏；A7 报告无"已验证为正品"表述含免责声明；A8 压测成本预估偏差<20%。
