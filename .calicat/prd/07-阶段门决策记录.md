## 关键决策清单

**G0 需求澄清**

* D-AAP-01：范围锁定"供应商自动化进件"闭环，不做客户端用户体系改造、不做 benchmark 排行。
* D-AAP-02：供应商端载体为小程序 + H5 一套代码自适应；管理端 Web。
* D-AAP-03：打款本期不进入系统资金流转，仅记录状态。

**G1 调研（new-api 能力基线）**

* D-AAP-04：new-api 零源码改动，全部集成走既有管理 API。
* D-AAP-05：认可 billingexpr 原生支持峰谷/阶梯/缓存价，业务报价可 1:1 表达，无需降级转换。
* D-AAP-06：记录缺口 F8——Log 表无独立缓存 token 字段。

**G2 洞察**

* D-AAP-08：产品定位为"供应商质量验真 + 自动计费编译"。
* 状态机以 PRD 总览 §4 英文枚举为权威口径。

**G3 可行性**

* D-AAP-09：缓存命中用量改走方案 C——AAP 自建小时用量表。
* D-AAP-10：模型指纹定位为"证据链 + 置信度"，不是证明。
* D-AAP-11：电子合同一期走线下，预留 sign\_channel=ONLINE。
* D-AAP-12：砍除系统内打款资金流转，改为仅记录状态与凭证。
* D-AAP-13：红线——编译产物未经模拟求值验证，禁止写入 new-api 生产环境。
* D-AAP-14：SSRF 与 Key 泄露列为高风险，M0 必须实现代理与加密。

**G4 商业（报价与编译）**

* D-AAP-15：报价单三层结构，单价统一 \$/1M tokens 真实单价，无倍率转换。
* D-AAP-16：组合策略唯一化——先分档（len）后分时段（hour）嵌套。
* D-AAP-17：阶梯条件必须用 len，禁用 p。
* D-AAP-18：编译器设三道闸门：编译 → 模拟校验 → 人工确认。
* D-AAP-19：请求级加价（|||）仅在管理端高级模式开放。

**G5 决策门（Go）**

* D-AAP-20：Go，按 plan.md 的 M0–M3 推进；M0 先打通"凭证 → 检测（4 项）→ 报告"。
* D-AAP-21：技术栈口径——Java 25；版本治理 `import com.hioas.framework:hioas-dependencies`。
* D-AAP-07（补录）：Spring Boot 版本口径修正，以 BOM 管理值为准，项目 POM 不得自行指定。
* D-AAP-22：责任人占位须由需求方指派人选后替换。
