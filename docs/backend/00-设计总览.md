## 5. 统一响应与错误码

```json
{ "code": "0", "message": "ok", "data": { }, "traceId": "..." }
```

- 成功 `code="0"`；业务失败 `code="E-xxxx"` + HTTP 4xx/5xx，`data` 为 null（**禁止用 0 冒充"没有数据"**）。
- 鉴权失败 HTTP 401 + `code="E-1902"`；权限不足 403 + `E-1901`；限流 429 + `E-1903`。
- 错误码全集见 `02-API接口模型清单.md` §4 与 `json-schema/common/error.schema.json`。

## 6. 验收标准（本轮 DoD）

1. 每个任务：**先红后绿**，红基线输出留 `logs/` 或 `.agents/state/evidence/`，任务收尾 `mvn test` 全绿且连跑两轮一致。
2. AC 用例（`.calicat/prd/21-验收标准.md`）逐条落到测试方法名，测试报告可对应。
3. 接口响应体经 `docs/backend/json-schema/**` 契约校验通过（`ContractSchemaTest`）。
4. 服务经 IDE/命令行启动，`/actuator/health` UP，`logs/aap-server.log` 无 ERROR/Exception。
5. `aap-client` 主链路（登录 → 凭证 → 检测 → 报告 → 报价 → 用量）能打到本服务并渲染。
6. 台账 `.agents/state/aap-server-feature-status.csv` 与状态文件 `.agents/state/aap-server-tdd-state.md` 回写。
