1. **派生器的「上一轮裸标签残留」判据**自指命中**：判据源码里的字面量被自己数成残留（3 处）**（派生/脚本侧缺陷；由派生器自身的硬断言当场拦下，**零产物落盘**）。（历史 47/191：判据与它要防的形态必须**分开承载**，否则自检永远不干净。）事实（机器可查）：产物侧从不含该形态（源产物实读 0 处），而 `_self_old` 的扫描对象是**派生脚本自身**，其判据字符串 `re.findall(r"MK" + "400" + "_", ...)` 一旦写成连续字面量，本文件就自带 3 处命中 ⇒ 「派生脚本自身残留 == 0」这条判据**恒为假**，派生器 rc=1、`MK401_BUILD_FAILS=1`。**危害**：这类自指命中会把**合规产物**判红（与第 2 项相反方向、同一族），若被「删掉判据」平息，同类真残留从此静默通过（历史 57/68/190）。修法 = 上一轮形态的判据一律**拆分构造**（`PREV_LBL = "MK" + "400" + "_"`、`PREV_BARE = "mk" + "400" + "-"`），判据字面量不再出现在本文件里；判别方式 = 该脚本自身 `_self_old == 0`。

2. **「本轮形态」本身是「上一轮形态」模式的一个实例 ⇒ 判据范围与语义不符**（判据侧缺陷；由同一次派生运行当场拦下）。（历史 81：判据范围必须与被判语义一致；历史 141/220-③：正向对照不得假定某个合规对象一定存在。）事实（机器可查）：残留扫描模式写作 `MK40[01]_`（想涵盖上一轮的两种写法），而本轮形态 `MK401_` **正是该模式的匹配对象** ⇒ 「产物残留 == 0」（反向守卫）与「派生脚本自身含本轮标签 ≥ 1 处」（正向对照）**互相矛盾**：同一模式不可能既为 0 又 ≥ 1。**危害**：两条断言中必有一条永远失败；若为让它变绿而放宽任一侧，就会得到「看起来有守卫、实则空转」的产物（历史 98）。修法 = 残留判据**只锚上一轮形态**（本轮形态由独立的正向对照断言）；且**承载面实读为 0 时不判 FAIL**，牙齿改由**合成对照**证明（段内/段外注入各 1 条 + 合成旧标签必须被替换、合成不存在脚本名必须被报出）。

3. **已知纪律复犯：无人值守下用 `-c` / heredoc 形式执行解释器**（流程侧缺陷；被安全策略**当场拦下**，零影响）。（历史 37：cron 下 `bash -c` / `python -c` / 任意本地 Python 一律被拦 —— 临时脚本必须先落盘为文件再调用。）事实（机器可查）：本轮为比对两轮归档的按族分布，先写成 `python -c "…"` 与 `python - <<EOF` 两种形态，两次均被策略拒绝并给出替代方案（`BLOCKED: script execution via -c/-e flag` / `via heredoc`），随即改为「`write_file` 落盘 + `python <file>`」（落盘脚本 `cmp-by-task.py` / `trace-bytask-r401.py`）。**危害**：被拦即中止，不会半执行；但同一习惯若落在**有副作用**的多步逻辑上，重试会让人误以为「逻辑失败」而去做无关排查。修法 = 沿用落盘式调用；本轮全部一次性脚本（体检 / 派生 / 取证 / 收尾）均为落盘调用。

4. **自撰证据脚本的判据计数写成 `len(PASS)` / `len(FAIL)` ⇒ 打印「PASS 1 / FAIL 1」与逐条结论自相矛盾**（判据/产物侧缺陷；由同一次运行的输出当场暴露）。（历史 12/95：产物不得自相矛盾；历史 82/93：自测自身的断言也会写错，且表现为「守卫看起来失效」。）事实（机器可查）：计数器形如 `PASS, FAIL = [0], [0]`，累计用 `PASS[0] += 1`（正确），而汇总行写成 `len(PASS)` / `len(FAIL)` —— 列表长度恒为 1 ⇒ 无论多少条判据都打印 `PASS 1 / FAIL 1`，与紧接着列出的「10 条全 PASS / 0 条 FAIL」互相打脸。**危害**：这是**汇总行**与**明细**不一致的典型形态（历史 103 族），评审只读汇总行就会误判本轮有失败项。修法 = 计数一律取 `PASS[0] / FAIL[0]`，并复核「汇总数字 == 明细 PASS/FAIL 计数」。

5. **新增的报告侧取证脚本把「本文件自身」算成陈旧读数的来源 ⇒ 追溯判据自指失败**（判据侧缺陷；由该脚本的 A1 断言当场拦下，**该断言本应是 PASS**）。（历史 47/222：本文件不得自判；判据的扫描集合必须排除本文件。）事实（机器可查）：脚本 A1 判定「含该陈旧读数的来源文件**全部早于上一轮**」，而本文件为了记录该读数**自身也含该串** ⇒ 来源列表里出现本文件、A1 恒假；排除本文件后来源回到 3 个更早轮次的证据文件（R373–R375）。**危害**：与第 1 项同族（自指命中）；若删掉该断言平息，则「陈旧引用」这一发现的**唯一机器证据**随之消失。修法 = 扫描集合排除 `SELF`，并把排除项**打印出来**（判据范围必须与语义一致，且豁免要可见）。

6. **定稿器的「同名遮蔽」守卫把**调用点**也算成定义 ⇒ 假失败**（判据侧缺陷；由同一次运行的断言当场拦下，**未落盘**）。（历史 81：判据范围必须与语义一致 —— 本轮第三次同族；历史 102：改脚本后先确认「该函数只定义一次」这条**语义**怎么落地。）事实（机器可查）：判据写作 `len(re.findall(r"ev_list\(\)", out)) == 1`，而产物里该名字出现**两次**（`def ev_list():` 定义行 + `EV_ITEMS = ev_list()` 调用行）⇒ 报出「定义数 = 2」，把**合规产物**判红；改成只数定义行（`(?m)^def ev_list\(\):`）后为 1。**危害**：与「同名遮蔽」这条真缺陷的指纹正好相反 —— 真正的遮蔽（两份 def）与「一 def 一调用」都会命中同一判据，于是修法（放宽判据）与依赖直觉得出的「消除遮蔽」都会走偏。修法 = 判据锚定**定义行**的语法形态，并在输出里写明「把调用点算进来会得到 2」这一反例。
