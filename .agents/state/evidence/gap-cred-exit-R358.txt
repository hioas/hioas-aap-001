R358 第 30 类只读取证 · 证据/产物里的**凭据出口**

为什么两套门禁都看不见：契约测试只把**真实响应体**与 JSON Schema 比对（证据文件里的令牌不是响应体）；
覆盖门禁只比「方法+路径」；openapi 与客户端 TS 不被任何测试读取/执行。
→ 「登录响应体原样进证据」这条链路**没有任何一套门禁覆盖**，而唯一相关的凭据门禁自身还有一个口径盲区（见 B2）。

== 判据（绝不回显值；Tier A = 键名承载密钥语义） ==
  JWT 形态：三段式 eyJ…（任意位置）
  键值形态：Tier A 键名 + 值 ≥12 字符，**单双引号都认**（含 Python repr：'refresh_token': '…'）
  值一律只输出 长度 + sha256[:12]。

== B 门禁口径（tools/evidence-secrets.py） ==
  B1 判别力实测（--selftest，本轮**新增**）：rc=0
     [PASS] json 双引号长值         期望=1 实得=1
       [PASS] repr 单引号长值         期望=1 实得=1
       [PASS] JWT 裸形态            期望=1 实得=1
       [PASS] 已脱敏不再计             期望=0 实得=0
       [PASS] 非密钥键不误伤            期望=0 实得=0
       [PASS] 短值不误伤              期望=0 实得=0
       自测通过 6/6
  B2 修前盲区（真实返工）：门禁的键值正则只认**双引号 JSON**（`"key": "value"`），
     而本项目的泄漏形态是 **Python repr（单引号）** → **不透明 refresh token（43 字符，非 JWT 形态）完全不被检出**；
     修前门禁报「命中 10 条」（只有 JWT），而本探针在同一批文件上检出 **KV_ANY=20 条** → 盲区 Δ=20。
  B3 修后：门禁 `--redact` 就地脱敏 5 个文件，复扫剩余 = 0。

== C 生成侧（谁把令牌写进证据） ==
  根因：tools/biz-closure-e2e.py 的 step() 把步骤返回值 `str(detail)` **原样**写进 RESULTS 与 stdout，
        而 dev_login() 返回的是**整个登录响应体**（含 token / refresh_token）→ 报告落盘即泄漏。
  修法：新增 mask_secrets() 出口，step() 的落盘与 stdout **都**走它（返回值保持原样，不改变调用方行为）。
