真实密钥泄漏比对（R27） — 证据说明
====================================
方法：把 `E:/env/*.env` 的真实值当**模式**去比对（值一律不回显，只输出 变量名 / 长度 / sha256 前 8 位）。
范围：本次**暂存差异**（`git diff --cached`）+ **提交历史**（`git show HEAD`）+ 本次改动的每个文件内容。

分层（**本轮修正了一个方法学缺陷**）：
  · Tier A = 变量名含 PASSWORD/SECRET/KEY/TOKEN/CREDENTIAL/CERT/PWD（共 13 个）→ **必须 0 命中**；
  · Tier B = 其余（HOST/PORT/NAME/USER/DATABASE…，共 7 个）→ 信息项。

**第一版脚本把 Tier B 也算作泄漏 → 报出 12 处「命中」的假发现**。逐条核对后确认是低熵**非密钥**字面量：
  · `DB_HOST`（len=9）= `localhost` —— 生成器与 openapi.yaml 的 server URL 里本来就有（`grep -c localhost` = 1/1）；
  · `DB_TEST_NAME`/`DB_NAME`（len=15/14）= 测试库/开发库名，**已在前几轮台账里公开写明**（`aap_server_test`/`aap_server_dev`），
    全量测试日志里必然出现。
规则：泄漏比对的模式集**必须按「名字是否含密钥语义」分层**，否则会把「库名/主机名」这类公开字面量当成泄漏，
反过来把「Tier A 真密钥 0 命中」这个真结论淹掉（踩坑 29/32 同族：假发现会掩盖真结论）。

结论：**Tier A（13 个真实密钥类变量）0 命中**；被跟踪的 `.env` 类文件只有 `aap-server/.env.example`（模板）。
