1. **派生产物的「正则口径」是机械滚动的独立盲区：形态过滤器的字符类 `40[01]` 滚不到 ⇒ 对本轮源恒不命中**（判据侧缺陷；由本轮新增的**派生后盲区枚举器**在生成任何产物之前发现并修正，零影响）。（历史 187/195/239-② 的固定指纹：口径过期方向是「更合规」—— 命中越少越像干净；历史 46/98：0 命中先怀疑判据。）事实（机器可查）：`scan-forms` 的形态过滤器在上一轮产物里写作 `[Rr]40[01]`（匹配更早两轮的形态），机械滚动只认 `[Rr]R\d{3}` 这种**带字母前缀**的形态 ⇒ 该字符类原样留在本轮产物里、指向错误的轮次区间，枚举结果为空。修法 = 显式改为 `[Rr]40[12]`（并把内层分类的 `402` 改成 `403`、分支与 print 标签同步），并配**正向对照**「新口径在上一轮四目录上命中 148 处（须 > 0）、旧口径命中 23 处」——没有这条对照，「0 命中」无法区分「真干净」与「口径失效」（历史 75/98/195）。

2. **「纯数字派生盲区」的第三类载体：只读探针脚本里写死的轮次计数 / 返工计数 / 证据条数**（判据侧缺陷；同上，生成产物之前由盲区枚举器发现并修正，零影响）。（历史 201/206/215/219/243-③：轮次计数、返工计数这类**纯数字**既不含字母也不含大写轮次号 ⇒ 机械滚动天然碰不到，每轮靠人手改；漏改即把上一轮的窗口事实写进本轮证据，构成**假自述**，历史 12/95 的机器可查形式。）事实（机器可查）：两份只读探针把期望值写成字面量（轮次计数 385 / 返工计数 1 处 / 证据条数 23），派生后它们会**恒判 False**（本轮真值不同），把「探针读数不合格」的假象写进收尾复核。修法 = **结构性消除**：探针的期望值一律从**事实来源推导** —— 轮次计数取分析 JSON 的 `streak`、返工计数与证据条数取本轮台账行（`本轮返工 N 处（判据侧）` 形态 + 证据列按 `；` 切分），源码内零硬编码纯值；并配反向守卫「重写后的探针不得再出现 `连续第 <数字> 轮` / `证据 <数字> 条` / `返工 <数字> 处` 字面量」（实测 0 处）。

3. **修正脚本自身的两处判据错误被自己的断言当场拦下 —— 崩溃方向正确（历史 175/245-① 的正例）**（判据侧缺陷；发生在**运行前**的修正环节，零影响）。（历史 46/225：0 命中一律先怀疑判据；历史 197/205/243-②：锚点必须回**实际产物**核对，源侧文件名属于**上一轮**、不是本轮轮次号。）事实（机器可查）：① 「源清单补齐」项的锚点按**本轮**轮次号写（`…-r404.sh`），而源侧清单里写的是**上一轮**名字（`…-r403.sh`）⇒ 锚点 0 命中、`repl1` 的三态判据响亮判「判据失效」；② 正则口径的**正向对照**只查了单个文件，而 R401/R402 形态恰好不在那个文件里 ⇒ 对照值 0、「修正后的口径恒不命中」被正确报出。修法 = ① 锚点改取滚动后文本里**实际存在**的源侧名字并断言命中恰好 1 次；② 正向对照的扫描范围改为**上一轮四目录全部文件**（实测 32 个文件 / 新口径 148 处 / 旧口径 23 处）。

4. **派生链的「阶段顺序」纪律第二次复犯：第 39 类 pre 段跑在报告侧取证之前 ⇒ 判据正确地报出「清单条目无解释」**（流程侧缺陷；由该脚本自身的硬断言当场拦下，零功能影响）。（历史 217-②：阶段顺序依赖必须机器化；历史 222：清单类判据必须区分「本阶段稍后产出」与「真缺失」；历史 191/243-①：收尾链的顺序纪律已在更早轮次登记过同类项。）事实（机器可查，**首跑读数逐字引用**）：`[FAIL] A0b 缺失条目**全部**有解释（本阶段稍后产出 8 ∪ 收尾期白名单 ∪ 本文件自身 1） | 未解释 = ['gap-report-claim-R404.txt']（缺失 6 条，其中已解释 5）`，汇总 `PASS=14 FAIL=1`；把报告侧取证（`gap-report-claim-r404.py`）**前置**到该段之前后复跑 ⇒ `PASS=15 FAIL=0 INFO=2`，零写副作用断言（受核 17 份 size+md5 全等）同时成立。**危害**：若为平息该 FAIL 去放宽「本阶段稍后产出」白名单，pre 段就再也检不出真正的缺失；反向若把它当「守卫失效」跳过，「报告侧取证先于第 39 类 pre 段」这条已登记的依赖就继续靠人手记。**据实说明（历史 12）**：首跑日志已被随后的复跑**覆盖**，故本项**不主张**「已保留首跑日志」，只以首跑读数逐字引用留证；下一轮起该段的调用顺序应写成**机器化的阶段依赖表**（已列入待拍板）。
