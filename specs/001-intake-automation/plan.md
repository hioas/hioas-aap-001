## 2. 总体方案

### 2.1 分层与模块归属

沿用既有 19 个包边界，新增与变更如下：

| 包 | 变更 | 职责 |
| --- | --- | --- |
| `supply`（新） | 新增 | 供给单元聚合：模型 × 供应商，状态机、质量画像、调度画像 |
| `sync`（既有，扩展） | 扩展 | 渠道绑定改造为按供给单元；新增批量编排 `ConfigBatchOrchestrator`、回读校验器、冲突检测 |
| `pricing`（新） | 新增 | 模型目录、模型价格表、渠道价格表、比价与毛利视图、漂移守护 |
| `intake`（新） | 新增 | 进件流水线实例：阶段推进、断点续跑、自动化等级判定 |
| `routing`（新） | 新增 | 模型级调度策略解析与权重计算（检测分数 + 质量反馈 → priority/weight） |
| `contract`/`settlement`/`quote`/`detection`（既有） | 微调 | 接入流水线编排（发布领域事件，由 intake 消费推进） |
| `support`（既有） | 扩展 | 审计动作枚举补配置/治理类动作 |

**依赖方向**：`intake → {supply, pricing, sync, quote, contract, settlement}`；
`sync → 网关 ACL`（唯一出口，宪法 §6.1）；`routing → supply + pricing`（只读）。

### 2.2 数据流

```
凭证提交 ─预检→ 检测 ──→ 报告 ──→ [自动化等级判定] ──→ 报价单(草稿/自动)
                                                     │
                                     审核 → 合同 → 打款 ─→ 配置编排(批量)
                                                     │
                        ┌────────────────────────────┴──────────────┐
                        │  供给单元 × N → 渠道(每模型一条) → 定价写入  │
                        │  读前对比 → 写入 → 写后回读 → 一致/告警重试  │
                        └────────────────────────────┬──────────────┘
                                                     ↓
                    渠道价格表(生效价) ──→ 用量归集 ──→ 结算/对账 ──→ 漂移守护
                                                     ↓
                                    质量反馈 ──→ 调权 ──→ 供给单元 priority/weight
```

## 3. 关键流程设计

### 3.1 进件流水线推进（FR-1）

- **事件驱动**：既有模块在状态变更时发布领域事件（`CredentialPrecheckPassed`、`DetectionFinished`、
  `QuoteApproved`、`ContractSigned`、`PaymentConfirmed`），`intake` 消费后推进阶段。
- **幂等**：`aap_intake_run.stage_history` 记录每次阶段变更；重复事件按 `(run_id, stage, event_id)` 去重。
- **断点续跑**（FR-1.8）：`stage_status = BLOCKED/FAILED` 时支持从该阶段重入；
  已完成阶段以 `stage_history` 判定，不重复执行。
- **人工介入**：L1 件在 `stage_status = BLOCKED` 且 `blocked_reason` 指明待确认项，管理端提供确认入口。

### 3.2 渠道批量配置（FR-2，核心）

编排器 `ConfigBatchOrchestrator` 五步：

1. **展开**：按 `aap_supply_unit` 生成待办项（供给单元 → 目标渠道配置）；
2. **差异计算**：与 `aap_channel_binding` + 网关现值对比，得到 `CREATE/UPDATE/SKIP/ENABLE/DISABLE` 动作；
   `SKIP` 判定依据为幂等键 + `source_hash` 一致（既有 R-34 的延续）；
3. **限速执行**（R-57）：默认 ≤5 req/s、每批 ≤20 条；优先用网关批量模式（research T-1 实测后启用，
   未实测则退化为串行单体创建 + 限速）；
4. **回读校验**（FR-2.6 / R-58）：逐条回读，比对名称、`base_url`、`models`、`status`、
   `priority`、`weight`；不一致 → `MISMATCH` + 退避重试（30s/2m/10m）；耗尽 → 转人工 +
   供给单元标记「配置未收敛」；
5. **收尾**：写 `aap_config_batch` 统计 + 更新 `aap_supply_unit.status`，发布 `ConfigBatchFinished`。

**单模型隔离**（R-59）：每项独立事务 + 独立幂等键；失败只回滚该项（删渠道或恢复原值），不波及其他。

**预演**（FR-6.3 / AC-10）：`mode = DRY_RUN` 时执行第 1–2 步并落 `diff_payload`，**跳过第 3–4 步**；
代码路径上以「执行器注入」区分，dry-run 注入的写入执行器为「空实现 + 记录」，确保零写入。

### 3.3 定价写入（FR-2.8）

沿用既有三闸门：编译 → 模拟校验 → 确认；本特性**不新增闸门，也不放宽闸门**。
写入路径按 research T-2 实测结果二选一（或并存）：

- 路径 A（既有）：写网关定价配置项 `billing_setting.billing_expr[model]`（DB 直连，默认策略）；
- 路径 B（新增候选）：调用网关定价配置 API（`/api/option/model_pricing`）。

无论哪条，写入后必须回读并落 `aap_channel_price.readback_hash`。

### 3.4 调度权重计算（INNOV-4 / FR-7.1）

```
weight = clamp( round( W_detect * detect_score_norm + W_quality * quality_score_norm ), min, max )
priority = f(provider_tier, supply_priority_override)
```

- 权重由 `aap_routing_policy.weight_rule` 配置（默认 `W_detect=0.4, W_quality=0.6`，`min=1, max=100`）；
- 计算任务按小时触发，**只在变化超过阈值时**回写网关（避免频繁改网关造成抖动）；
- 每次回写留痕（依据哪次检测/哪个质量窗口），满足 R-64 可解释性。

### 3.5 价格漂移守护（FR-7.2 / R-63）

- 数据源：上游倍率同步结果 与 结算对账实际单价；
- 对比 `aap_channel_price` 生效价，`|drift| > 5%` → 写 `aap_price_drift` + 告警；
- 连续两个周期未处理 → 自动降权（`action_taken = WEIGHT_DOWN`）；
- **自动停用默认关闭**（Q-6），需管理端显式开启。

## 4. 幂等、重试与回滚

| 动作 | 幂等键 | 重试 | 回滚 |
| --- | --- | --- | --- |
| 建渠道 | `sha256(provider_id\|ADD_CHANNEL\|channel_name)` | 30s/2m/10m，鉴权类不重试 | 删除该渠道（仅该模型） |
| 改渠道 | `sha256(channel_id\|UPDATE_CHANNEL\|payload_hash)` | 同上 | 恢复写前快照 |
| 写价格 | `sha256(provider_id\|WRITE_EXPR\|model\|source_hash)` | 同上 | 恢复 `previous_expr` |
| 启停 | `sha256(provider_id\|TAG_STATUS\|目标状态)` | 同上 | 反向操作 |
| 供给单元展开 | `sha256(intake_run_id\|EXPAND\|model)` | 无需 | — |

**统一纪律**：外部写操作必须「读前对比 → 写入 → 写后回读」；不一致**告警**而非静默成功（宪法 §6.5）。

## 5. 安全

| 项 | 措施 |
| --- | --- |
| 凭证 | 密文存储（既有）；仅 ACL 解密后写入网关；`request_summary` 中 key 一律 mask；全链路日志扫描（AC-18） |
| 批量操作 | 影响面超阈值（默认 50 条或涉及 > 5 个供应商）需二次确认 |
| 治理动作 | 降权/停用/下线全部审计（C-07），含依据与操作人 |
| 权限 | 批量配置与调价限 SUPER_ADMIN 或显式授权角色；供应商端只读自己的数据 |
| 出站 | 沿用统一出站网关（SSRF + 超时 + 重试 + 脱敏） |

## 10. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 网关批量模式 payload 与预期不符 | 中 | 首日实测；不符则退化为串行 + 限速（功能不减，仅时长增加） |
| 渠道数 M×N 膨胀影响网关性能 | 中 | M4 末压测；超阈值自动对长尾模型启用合并模式（DR-03） |
| 多 Key 模式语义不确定 | 中 | T-3 实测；不确定则保守用单 key 多渠道路径并记录泄露面风险 |
| 定价写入路径选错（表达式 vs 定价配置） | 高 | T-2 实测 + 双写开关，回读校验兜底 |
| 回读不一致被忽略 | 高 | 硬约束：不一致必须落 `MISMATCH` 清单且看板可见（AC-02/R-58） |
| 全自动放太早出事故 | 高 | 默认 L1；L2/L3 按白名单逐步放开；闸门②永不可跳 |
| 既有渠道迁移风险 | 中 | V15 **不迁移**既有渠道，只登记供给单元；拆分按批次显式触发 + dry-run |
